#### 1. 为什么选 ECS？
*   **解耦**：武器逻辑、移动逻辑、渲染逻辑完全分离。比如“橡皮擦敌人”只是一个拥有 `EraserComponent` 的实体，修改它的行为不需要改动整个 `Enemy` 类。

### 4. 关键设计决策

*   **双层渲染循环 (Dual Render Loop)**：
    *   **Layer 1 (Trail Layer)**：`trailCanvas`。只在有颜料产生时绘制，**不每帧清空**。这是我们的“画板”。
    *   **Layer 2 (Game Layer)**：`gameCanvas`。每帧清空重绘。显示玩家、敌人、子弹、UI。
    *   *优化*：使用 `OffscreenCanvas` (如果浏览器支持) 来处理复杂的轨迹绘制，避免阻塞主线程。

*   **事件驱动 (Event Driven)**：
    *   不要在 `Player` 里直接调用 `SoundManager.play('shoot')`。
    *   而是发出 `EventBus.emit('SHOOT', { type: 'pistol' })`。
    *   这样音频系统、特效系统、UI系统都可以监听这个事件，互不干扰。

*   **状态机 (State Machine)**：
    *   游戏状态：`Menu` -> `Playing` -> `Paused` -> `GameOver` -> `Gallery`。
    *   玩家状态：`Idle` -> `Moving` -> `Shooting` -> `Dead`。

### 1. Vite + TypeScript (当前方案) vs. UniApp

| 特性 | Vite + TypeScript (原生 Web) | UniApp (跨平台框架) |

### 2. 为什么 UniApp 不太适合《涂了个鸦》？

UniApp 非常适合做 **“应用型”小程序**（比如电商、工具、资讯），或者简单的**点击类小游戏**。

但《涂了个鸦》是一个 **高频动作射击游戏**：
*   **每秒 60 帧刷新**。
*   **大量的粒子效果**（爆炸、血迹、轨迹）。
*   **高频的触摸交互**（双摇杆）。

UniApp 的架构（基于 WebView 和 JSBridge）在处理这种高强度的 Canvas 渲染时，往往会遇到性能瓶颈。而且 UniApp 的 Canvas API 封装有时跟标准 API 不完全一致，迁移起来坑比较多。

### 1. 核心架构：ECS (Entity-Component-System)
ECS 是现代游戏开发中最流行的架构之一。在这个工程里，它就像是剧组的人员分工：

*   **Entity (实体) = 演员/道具**
    *   在代码里，玩家、敌人、子弹、粒子，甚至摄像机，统统都是 `Entity`。
    *   它们本身只是一个空壳（只有一个 ID），就像一个还没化妆、没穿戏服的群演。
    *   **代码位置**：[Entity.ts](src/core/Entity.ts)

*   **Component (组件) = 戏服/道具包/剧本设定**
    *   为了让“群演”变成“主角”，我们需要给它挂上各种组件。
    *   挂上 `Transform`（位置组件），他就在舞台上有位置了。
    *   挂上 `Renderable`（渲染组件），他就穿上了衣服（有颜色、形状）。
    *   挂上 `Control`（控制组件），他就能听导演（玩家）指挥了。
    *   **代码位置**：[Transform.ts](src/components/Transform.ts), [Renderable.ts](src/components/Renderable.ts) 等。

*   **System (系统) = 导演组/后勤组**
    *   这是真正干活的人。每个系统只负责管自己那摊事儿，它会遍历所有挂了对应组件的实体。
    *   `MovementSystem`（移动组）：只盯着有“位置”和“速度”的人，每帧更新他们的位置。
    *   `RenderSystem`（摄影组）：只盯着有“渲染”属性的人，把他们画在屏幕上。
    *   `InputSystem`（动作指导）：监听键盘鼠标，告诉主角该往哪动。
    *   **代码位置**：[MovementSystem.ts](src/systems/MovementSystem.ts), [RenderSystem.ts](src/systems/RenderSystem.ts) 等。

这个游戏之所以叫 "Dont Erase Me"，是因为它用了**分层渲染**技术，就像画画时用了好几张透明纸叠在一起：

1.  **最底层：世界痕迹 (TrailCanvas)**
    *   这是一张**巨大的画纸**（2000x2000像素），比屏幕大得多。

3.  **最顶层：UI与小地图 (UICanvas/Minimap)**
