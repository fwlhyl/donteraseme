# 统一清晰度重绘：背景与 UI

制作日期：2026-10-18。接入与验证收尾：2026-10-20（Asia/Shanghai）。

本轮按用户批准的创造模式重绘版推广，保留已确认的暗纸、灰褐建筑、骨白笔迹与少量锈红风格。主要调整是减少细碎纸纤维和椒盐状磨损，合并安静的大色面，让建筑、道具和文字边缘更明确；没有改成另一种美术风格，也没有更改玩法、地图尺寸或碰撞边界。

## 来源与制作记录

- 使用内置 **imagegen 图像编辑**，以现有素材为编辑目标、已批准的创造模式重绘为清晰度参考，没有改用 CLI。
- 五张后续重绘的完整提示词及编辑目标见本目录 `prompts.json`；生成来源与运行文件映射见 `manifest.json`。
- 创造模式先行版本沿用 `../atelier-hd-review-2026-10-18/atelier-clarity-v1.png`；其提示词和审阅过程记录在该目录中。
- 所有素材保留原画面布局、主要物体、配色和视觉层级。实际游戏中的画布、存档作品、导出图与回放不烘焙这些背景。

## UI 与画廊采样

UI 继续使用已经批准的布局与视觉语言。本轮将公共纸纹改为稀疏、低对比的 512 × 512 SVG 纤维，不使用滤镜噪点、模糊或位图放大；HUD 文字保留清楚的偏移阴影，没有模糊光晕。主菜单插画按原 16:9 舞台显示，模式按钮、文字和交互仍由实时 UI 绘制。

画廊墙面和地面复用两张材质，启用上限为设备能力与 4 的较小值的各向异性过滤，保留 mipmap，减少斜视墙面/地面采样发糊。画廊 DPR 仍限制为 1.5，无实时阴影；本轮没有以整体提高渲染分辨率换取更高 Mac 显存和填充负载。收藏作品维持原色，无背景色调滤镜。

### 纯画画恢复断言的收尾说明

原测试用第一次 `canvas.toDataURL()` 的结果作为唯一恢复基线，遇到了 Chromium 重复读回时的 GPU/CPU 栅格路径切换。诊断时，**完全未污染、相同参数**的连续控制重绘也会先产生 DPR 1 下 5 个通道、DPR 2 下 18 个通道各 1 级的差异；切换时分别有 956,807 / 3,806,287 个通道变化，最大差异 21 / 23。后续控制帧与恢复帧均完全一致，未发现 `DrawingScene` 恢复逻辑错误。

测试修复只在测试文件内：先固定进行读回预热，然后要求未污染控制帧**逐 RGBA 字节一致**，确认测试覆盖确实污染了画布，最后要求场景恢复后的像素**仍逐字节一致**且只增加一次绘图。没有放宽容差，没有更改运行时场景逻辑。审阅截图在读回预热之前拍摄，避免测试读回主动改变截图的正常显示路径。

## 已知限制

- Retina 下仍存在源图到世界尺寸的放大；本轮解决的是视觉细节过密和边缘含混，不宣称根治所有分辨率限制。
- 本轮没有对人物、敌人、武器形象进行重制。
- 自动化验证确认展示、交互、作品隔离和缓存行为，不等于本机 Mac 后期高敌人数的完整性能验收；不据此宣称帧率问题已经解决。
