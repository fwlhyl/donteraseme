## 0. 共同地基：笔迹日志（Stroke Log）

回放与神笔马良都依赖**笔迹数据**，而现状游戏只做光栅绘制（直接画 trailCtx），不留数据。所以功能的第一步是同一个：**在现有绘制调用点旁追加记录**。

- 玩家移动轨迹：TrailSystem 画 trailCtx 处
- 武器弹道轨迹：WeaponSystem 画 trailCtx 处
- 闭合图形填充/击杀绽放/技能色块：GraffitiSystem / SkillSystem 等事件处

**日志格式（轻量）**：
```ts
type StrokeRecord =
  | { t: number; kind: 'move' | 'shot'; points: [x,y][]; color: string; width: number }
  | { t: number; kind: 'fill' | 'bloom'; x: number; y: number; radius: number; color: string }
// t = 局内毫秒时间戳
```

**要点**：
- **按距离抽稀**：新点与上一点距离 < 2~3px 不记录（20 分钟局全量约 3~10MB，抽稀后可控）
- 单局日志只存内存，局内生成、结算使用、离开结算后丢弃
- 想做"历史局回放"时再落 **IndexedDB**（容量比 localStorage 大两个数量级；localStorage 已存画框 PNG 不能再塞日志）

**三层笔迹通道（09-29 定案思路）**——日志记录一切，**消费方按通道挑数据**：

| 通道 | 来源 | 消费方 |
|---|---|---|
| ① 走位轨迹 | 玩家躲怪的被动笔迹 | 回放 / 作品层 |
| ② 武器自动输出 | 直线/弯线/喷射等弹道 | 回放；识别**不看**（噪音层，策展分流也用它） |
| ③ 主动作画 | 马良 v2 画板上的笔迹 | 识别层——识别器**只吃这一层** |

马良 v2 采用独立画板后，③ 天然与①②隔离（板子是独立 UI 表面），识别侧无需噪音过滤；三层划分主要服务回放与未来策展（ArtCurationDesign 的噪音箱 = ②的去处）。

## 1. 作画回放（✅ 09-29 提升至 v1.0）

**价值**：结算时把整局作画过程以快进重放——玩家看到自己 20 分钟笔迹在纸上重新生长。天然的自传播素材（短视频剪辑"我打一局画了一幅画"），也是结算仪式感。

**实现**：
1. 录制：§0 的笔迹日志（每帧在绘制点旁 record）
2. 结算界面（gameOver 屏）加"回放"按钮：停掉主循环，用 requestAnimationFrame 独立驱动回放循环
3. 渲染：按时间戳顺序重放日志条目，**复用现有的笔迹绘制函数**（视觉与真实作画一致），画到一个新的全图画布
4. 视角：固定全图俯视（3000×2000 等比缩到屏幕内）——看整张画布被逐渐画满
5. 速度：默认 30×（20 分钟 → 40 秒），提供 10×/30×/跳过 控制
6. **高光跳过**（可选优化）：连续 X 秒无笔迹的空白期直接跳帧（静置/跑图期压缩掉），把回放压到 ~30 秒精华版

**工作量**：日志录制 0.5 天 + 回放渲染/UI 0.5 天 ≈ **1 天 Codex**（神笔马良复用日志后另算）

**坑预告**：①日志只记"已画出的"——局内 alpha 消隐、橡皮擦擦除不记录，回放呈现的是"理想完整版"（先接受，擦除回放是后期优化）②录制时别在热路径新建对象，复用数组。

## 2. 神笔马良（✅ 09-29 提升至 v1.0，v2 方案）

**v1 原案（09-28，已废弃）**：战斗中画出固定图案（圆/方/三角/星）即触发。核心风险"边躲边画圆"难解，且武器自动线（直线/弯线/喷射）会污染识别。

**v2 方案（09-29 用户设计）**：
1. **攒条**：杀敌充能进度条
2. **开板**：条满后玩家**按键触发**（自选时机，像放大招；条满自动弹会打断走位=负反馈）——开板瞬间**游戏暂停**（时间停止；鼠标操控下光标被板占走无法躲，不暂停没人敢开板）
3. **画板**：全屏独立 UI 画板，显示**图纸模板**（v1.0 三张：坦克 / 飞机 / 机器人）
4. **临摹**：照着图纸描（认知负荷从"凭空想形状"降到"描线"，不需要会画画）
5. **识别**：$1 一元笔画识别器（见下），松手即识别
6. **收益**：匹配 → 获得对应**临时武器**（持续一小段；画得像→满额时长、大概像→打折时长）
7. **放弃**：ESC 取消本次（进度不返还，防"开了又关"当免费喘气按钮）

**技术路径：$1 一元笔画识别器**（Wobbrock et al., 2007，~200 行 TS，专为单笔画手势设计）：

```
画板笔迹
  → 重采样到固定 64 点（消除速度差异）
  → 归一化：平移到质心 → 缩放到单位大小 → 旋转到标准角（消除位置/大小/朝向差异）
  → 与模板逐个打分（路径平均距离）
  → 分数超阈值 = 命中
```

- 模板 = 图纸同源（坦克/飞机/机器人的轮廓点列），识别器与图纸共享一份数据
- 召唤本体复用火柴人助手（SummonSystem）代码
- **v2 消灭了 v1 的两大风险**：①战斗画图难 → 暂停画板专注描图 ②武器线型污染识别 → 画板是隔离表面，识别只吃板上的笔迹
- ✅ 09-29 拍板：图纸池 v1.0 = 坦克/飞机/机器人三张（后续更新扩充）；⏳ 画板产出是否进画廊收藏仍未定（推荐进——白赚留存钩子，与每日画展相通）

**工作量**：画板 UI + 进度条 + 识别器 + 临时武器授予 ≈ **2~3 天 Codex**

## 3. 金币系统最小版（✅ 09-29 纳入 v1.0）

局内金币已完整（怪掉金币 goldValue 1~500 / Score.coins / 收藏家金币倍率 / 局内买创作时间）；缺**持久化 + 角色解锁商店**（localStorage 只有画框）。

- **金币持久化**：localStorage 存累计金币
- **角色解锁商店**：8 角色用金币解锁（武器免费）；**收藏家免费初始**（09-28 用户已确认，与设计案「初始人物」一致）
- 理由：收藏家被动就是为经济设计的 + 品类标配留存钩子
- **工作量**：≈ 1 天 Codex

## 4. 守卫模式（🆕 09-29 提案；AI 评价=目前最强点子；排期待定 A/B/C）

**用户原案（09-29）**：开局一张画已印在画布上，玩家要守卫这幅画——敌人可擦掉画的某部位/全部，主角守卫的同时留下自己的痕迹。

**为什么强**：
- **主题命中到字面**：「Don't Erase Me」= 一幅画求你别擦掉它；无尽=你画（创造/休闲），守卫=你护（目标/紧张），两模式合起来标题才讲完整
- **治好「被动笔迹无聊」诊断**（09-28）：敌人分兵啃画 → 玩家必须**主动移动到被啃位置拦截**（空间控制/取舍判断=用户 20MTD 口味）
- **终局画 = 原画 + 战痕 + 玩家笔迹** = 每局唯一合作画作 → 进画廊/导出/回放（天然营销素材）

**技术实现（印画完全可行，已实证机制现成）**：
- 擦除机制已在引擎里：`trailCtx`（Game.ts:64）为主墨迹画布，`destination-out` 已在用（Game.ts:1220 时间消隐），EnemySystem 已持有 trailCtx（Game.ts:373，橡皮擦敌人擦笔迹）——原画层照抄同一套
- **印画 = 笔迹化打印**：一幅画就是一个 stroke log 文件——开局用回放引擎"播放"到画布上（复用 §1 的回放绘制函数）。画的来源：手写 SVG 路径转笔迹，或用编辑器画一次存日志
- **分层画布**：paintingCanvas（原画，在下）+ trailCanvas（玩家笔迹/弹道，在上）。橡皮擦敌人对两层都做 `globalCompositeOperation='destination-out'`
- **残存率判定**：定期 `getImageData(paintingCanvas)` 统计 alpha>0 像素 / 开局总数 = 残存率（3 秒采样一次，勿每帧算）→ 低于阈值判负
- 若嫌笔迹化麻烦，**光栅位图路线**也可行：drawImage 印 PNG + 同样的 destination-out 侵蚀——更简单，但损失"终局画=可回放日志"的收敛红利

**玩家上传图（✅ 09-29 拍板进 v1.0，笔迹化路线）**：玩家上传图片 → 转成游戏内线稿风格 → 印上画布 → 守自己的图（情感绑定最强档 + 主播素材"观众让我守这张图"，与每日画展晒画同族）。

- 管线：`<input type="file">` → FileReader → Image 解码 → 缩放 + **智能内容裁剪**（边缘检测找内容包围盒，去白底）→ **照片→线稿**：灰度 → Sobel 边缘检测 → 阈值 → 轮廓追踪（marching squares）→ 折线转 stroke log → 回放引擎播放到 paintingCanvas（与内置画完全同路）
- **转出的线保持 3~6px 笔宽**（太细一擦就断）
- 存储：处理后 stroke log 存 **IndexedDB**（勿塞 localStorage，已存画框）
- 纯本地、无分享 → Steam 无 UGC 审核风险，商店页可放心宣传
- 工作量：上传+裁剪 0.5~1 天 + 照片→线稿滤镜 1~2 天 ≈ **2 天 Codex**（未含滤镜调参）

**软擦机制（✅ 09-29 拍板）**：擦除 pass 用半透明（alpha≈0.4~0.5），**要擦几遍才擦没**——给玩家赶到现场的反应时间；被啃处有"半褪色伤疤"过渡态，与补画机制天然配合。内置画/上传线稿都是稀疏笔迹，硬擦（alpha=1 一次擦净）一碰就断，故守卫模式全局用软擦。

**✅ 已定案（09-29 晚）**：
- **失败条件**：玩家死亡 = 败；**画被完全擦没 = 立即失败**（人活着也算败，画=第二条命）；**守满 20 分钟且画还在 = 胜**
- **补画机制 = A 像素级修复**：玩家笔迹落在原画内容包围盒内 → 同一笔迹也画到 paintingCanvas（source-over 加回像素，残存率回升）；包围盒外只画 trailCanvas。终局画 = 原画 + 修补痕共存（伤疤与修补共存）。平衡旋钮 = 修复速度 vs 侵蚀速度，真玩调参。（B 描摹级 = 鬼影线 + 重叠检测恢复原笔画，发布后可选）
- ✅ **时长 = 20 分钟**（与无尽模式一致，09-29 用户定）

**排期**：✅ 09-29 晚用户选 A：完整进 v1.0（发布时间可推迟、2D 定案）；检查点：①10 月中功能全通+首轮 build ②11 月初调参收敛+商店页提交审核 ③11 月底上架。

**工作量**（完整版）：印画播放 + 分层画布 + 敌人分兵 AI（部分追人部分啃画）+ 软擦 + 胜负判定 + 上传笔迹化 + 波次调参 ≈ **4~6 天 Codex + 调参只能真玩**

## 5. 每日画展（仍 v1.1）

**价值**：留存工具——每日固定约束（同角色同武器），全员在相同规则下作画，比评分、晒画。

**无需自建服务端**：

| 需求 | 方案 |
|---|---|
| 每日统一约束 | 种子 = 日期字符串（如 "2026-10-01"）哈希 → 本地确定性生成角色/武器组合，全世界一致 |
| 排行榜 | Steam Leaderboards（Steamworks 免费自带），每日一个 board，提交评分 |
| 晒画 | 导出 PNG（已实现）+ 玩家自发截图分享 |

- 入口：主菜单"今日画展"卡片（今日角色/武器/我的评分）
- 只有"云端画廊/点赞投票"社交形态才需要自建服务端——最远期、收益不确定，暂不立项（真做可复用用户 2核4G 服务器）
- 注意：上架后才能接 Steamworks 排行榜，本地种子部分可提前做

**工作量**：种子系统 + 入口 UI ≈ 0.5 天；Steam 排行榜接入 ≈ 0.5 天（上架后）

---

## 6. 顺手项：胜败不同画

胜利 = 完整导出；失败 = 导出前加一遍"擦除侵蚀"pass（橡皮擦痕/边缘侵蚀）。新奇度低、情感价值有、成本 ≈ 装裱管线里一条 if 分支——跟着画作管线顺带完成，不单独排期。

## 7. 备选池（上架后按玩家反馈再挑）

| 编号 | 点子 | 一句话 |
|---|---|---|
| ③ | 画作即资源 | 擦掉自己的画换爆发/回血/reroll——美术价值 vs 战斗力 |
| ④ | 装裱占点 | 占点区域画作"上框"：不再消隐、免疫擦除 |
| ⑥ | 纸材质区域 | 水彩区晕染/蜡笔区不沾/素描区——地形影响笔迹 |
| ⑧ | 画圈封印 | 对 BOSS 画闭合圈触发封印伤害 |
| ⑨ | 修正带武器 | 玩家画白区域成为橡皮擦敌人禁地 |

另保留：BOSS 机制补全（棱镜护盾等）、玩法深化、角色规则化（Brotato 式）、难度分级、成就。

## 附录：美术风格分层（09-29 定方向）

用户抖音刷到水彩风决定采用（主题同源：水彩晕染≈擦除痕迹质感）。**素材规格实证**：角色帧=32×32 条带（8 帧/方向），渲染 1.5x≈48~60px 屏上尺寸——水彩晕染在游戏内 sprite 必糊。**分层落地**：

| 层 | 水彩怎么活 | 载体 |
|---|---|---|
| 游戏内 sprite | 只留骨架：高对比轮廓 + 大色块 + 留白 + 深色点缀 | 32×32 角色/怪物帧 |
| 水彩血肉 | 晕染/水迹/纸纹 | 角色选择立绘（1008px 先例）、UI、商店页、结算装裱 |

生成管线：高清生成 → 降采样 32×32（最近邻+调色板量化）→ 关键部位手修几像素；角色/怪物走"单帧立绘+代码动画"（勿让 AI 画逐帧）。一致性三招：风格锁 / 全家福样张当参考图 / 已确认的统一风格图当锚点。
