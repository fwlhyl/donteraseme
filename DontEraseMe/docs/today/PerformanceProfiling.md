# 性能测试手册（2026-10-13）

> 目的：定位 Mac（M5 Air 24G）上的卡顿。工作机（中低配 Windows + Unity/编辑器同开）浏览器 dev 模式已实测全程 60fps、JS 逻辑仅 0.7ms/帧——逻辑不是瓶颈，问题大概率在 macOS 渲染路径或环境负载。本手册三层递进，一次排除一层，10 分钟起步。

## 一、"浏览器 dev 模式"是什么

- 游戏本体是纯 Web 技术（HTML + Canvas + TS）。`npm run dev` = Vite 开发服务器，在**浏览器**（Chrome）打开 `localhost:5173` 游玩——这就是"浏览器 dev 模式"。
- `npm run electron:start` = Electron（本质是 Chromium 壳）加载构建产物——桌面版，Steam 发布的就是它。
- 两者渲染引擎相同（都是 Chromium），dev 模式只是按需编译、方便 F12 调试。性能结论基本可互推，**先测浏览器（能贴控制台脚本），发布前再补一轮 Electron 版验证**。

## 二、测试前准备

1. 拉最新代码（含本手册和 `scripts/` 下三个文件）：
   - `prof-console.js` —— 真实游玩采样（零依赖，F12 粘贴）
   - `prof-live-run.mjs` —— 自动压力场景（需 playwright + Chrome）
   - `gpucheck.mjs` —— 查 GPU 加速状态（需 playwright + Chrome，结果仅供参考）
2. 依赖：控制台脚本零依赖；另两个脚本需要 playwright，没装过就 `npm i --no-save playwright`（不写进 package.json），并确认本机装了 Chrome（脚本用系统 Chrome）。
3. 启动：`cd DontEraseMe && npm run dev`。

## 三、第一层：干净环境复测（10 分钟）

1. **退出所有无关软件**：浏览器其他页面、Codex、听歌软件、VPN——只留游戏。Air 无风扇会降频，VPN 也可能拖渲染，这一层必须干净。
2. 打开游戏，创造模式打一局，重点观察**开局 3 分钟**（第二轮优化后开局就卡的点）。
3. 结论：
   - **不卡** → 问题是环境负载/降频，不是代码。记下"干净环境不卡"结论，测试结束（如需预防：demo 录制和演示前关闭后台）。
   - **还卡** → 进入第二层。

## 四、第二层：采样定位（15 分钟）

1. 游戏开始后 `F12` → Console → 粘贴 `prof-console.js` 全文回车，看到「✅ 性能采样已开启」。
2. 正常玩，**感觉到卡的当下**输入 `__profReport()` 回车。
3. 判断依据：
   - 各系统 avg 之和（系统合计）很小（<3ms）、但平均帧 >20ms → **渲染/环境层**，做第 4 步回归开关实验。
   - 某个系统 avg 明显大（>3ms）→ 逻辑层热点，直接把表格发回。
4. 回归开关实验（定位第二轮优化是否引入回归）：
   - 输入 `__profNoClip()` 关闭第二轮引入的「每帧共享 clip」→ 再玩 1 分钟 → 再 `__profReport()` 对比。
   - 帧率恢复 → 回归点 = clip；没变化 → 再输入一次 `__profNoClip()` 恢复原状，回归点在别处，把两份报告都发回。
5. 截图或复制报告内容发回。

## 五、第三层：浏览器 vs Electron（5 分钟，第二层无结论时做）

1. `npm run electron:start` 打开桌面版，同场景打一局对比。
2. 浏览器流畅而 Electron 卡 → Electron GPU 配置问题（改 `electron/main.cjs` 加开关，一行的事）。
3. 两边都卡 → 回归点仍在游戏代码，等第二层数据。

## 六、注意事项清单

1. `prof-console.js` 必须在**游戏开始后**粘贴（要求 gameInstance 已存在且在运行）。
2. `__profReport()` 是**累计口径**：从粘贴那一刻开始统计，之后每次报告都是全时段平均。想看某一段（比如刚卡的那 30 秒）就刷新页面重新粘贴。
3. `__profNoClip()` 会关闭笔迹的地形裁剪（画面会脏、笔迹会画出墙外）——纯测试开关，**测完必须刷新页面恢复**，别带着它继续玩。
4. 采样本身有微小开销（每帧一次计时），可忽略，别因此不敢贴。
5. **第一层必须干净环境，第二层保持和平时一致**——两层目的不同，别混。第一层要回答"是不是环境"，第二层要回答"是哪段代码"。
6. M5 Air 无风扇：长时间高负载会降频。记录"连续玩了多久开始卡"——若干净环境下开局不卡、20 分钟后才卡，那是降频而非回归，也算结论。
7. 采样期间别切到别的应用窗口（页面切后台 rAF 暂停/降频，数据会乱）。
8. `gpucheck.mjs` 结果仅供参考：`node scripts/gpucheck.mjs`，看 GPU 设备名是不是"Apple Software Renderer / SwiftShader"（是 = 软渲染，报回来）。权威判断以第一层实测为准。
9. 报告别只发"还是卡"三个字——按第七节清单给数据。

## 七、回传数据清单

- `__profReport()` 完整表格（截图或文本，最好两份：开关前/开关后）
- 卡的时间点（开局几分钟？）和当时大概的敌人数量/笔迹密度
- 测试时开了哪些后台软件（第二层阶段）
- 浏览器还是 Electron、浏览器类型（Chrome 版本）
- 干净环境（第一层）的结果：开局卡不卡
- 第三层对比结果（若做了）
