# 角色动作改造任务书（部件动画 + 动作设计 + 打击感盘点）

> 日期：2026-10-21。状态：待执行（等用户 push 新人物立绘后开工）。执行人：Codex；验收人：用户。
> 本文是 2026-10-21 用户与 AI 讨论定案的自包含任务书，范围与验收以本文为准。

## 一、背景与现状

- 现役角色资产 = **单帧整图 sprite + 程序化摆动**（DoodleMotion 整图 bounce、DoodleWeapons 手持点贴图）。用户实测反馈：**动作僵硬、不自然**——走路只是平移加弹跳，射击只是"手抬起来贴上一个武器"，只有走路/转向/射击三个机械状态，达不到 demo 标准。
- 已定案：**问题在执行层，不在风格层**。风格锁（暗纸手绘：炭灰 #252621 / 米白 #eee4c8 / 锈红 #b74736、阿瑞斯病毒参考）一根手指不动。
- 改造方向：**部件动画**（AI 拆件一次 + 代码驱动动作）+ **动作设计清单**（姿态剧本）+ **打击感六味盘点**。
- 参考对象：黎明前 20 分钟（20MTD）——**抄它的动作节奏与反馈参数，不抄画面**。

## 二、核心决策（用户已拍板）

1. **不集成骨骼动画库**（Spine/DragonBones 等）：6-8 个部件的位移/旋转/缩放动画手写实现，避免外部库适配税。
2. **帧动画重新可行，双管线定案（2026-10-21 更新）**：AI 视频模型（MiniMax 海螺 / Seedance）逐帧生成天然帧连贯，"绿幕视频 → 抠图 → 裁连续帧"可产出帧动画。**管线 A（首要目标）= 视频转帧**；**管线 B（备选）= 部件动画**（AI 拆件 + 代码驱动）。
3. **只做收藏家完整动作**：demo 主角；其余 7 角色共用同一套动画驱动，只换部件图。
4. **参考图锚定比例**：先有完整立绘（用户将 push 的最新人物图），再拿立绘当参考图让 image_gen 出各部件，防止部件比例漂移（参考图锚定 > prompt 迭代，项目已验证）。
5. **管线裁决 = 实验三问**：管线 A 先做实验（见第三节），三问（风格锁 / 64px 清晰度 / 帧对齐）全过走 A，任一不过回落 B，不反复不并行。

## 三、管线 A：视频转帧（首要目标，实验先行）

**来源**：用户所在 AI 游戏开发群分享的成熟管线（2026-10-21 用户拍板优先尝试）。AI 视频模型（MiniMax 海螺 AI / Seedance 字节即梦）逐帧生成，帧间连贯性天然存在，解决了"AI 画不了连贯帧"的旧认知问题。

**流程**：
1. 用海螺 AI / Seedance 生成角色动作视频，提示词要求：**纯绿色背景**（色度键抠图）、暗纸手绘风（炭灰 #252621 / 米白 #eee4c8 / 锈红 #b74736，参考图=用户 push 的收藏家立绘）、指定动作循环（走路/射击/待机）、角色尽量固定居中。
2. 视频抠绿（FFmpeg chroma key 或 PIL 色度键）→ 按游戏帧率需求抽帧（8-12fps）→ 裁剪角色边界 → 逐帧对齐（角色漂移校正）→ 拼 sprite sheet 帧动画。
3. 渲染层支持帧动画播放（atlas 帧序列；现役为单帧+程序化，需对应改动）。

**实验验收三问（任一不过 → 放弃管线 A，回落管线 B）**：
1. 风格锁得住吗——暗纸手绘 vs 视频模型写实倾向。
2. 64×64 目标尺寸下线条糊吗——1080p 裁缩到 64px 是已知风险。
3. 帧漂移可对齐吗——视频角色位移的裁剪校正成本是否可控。

**成功则**：角色/敌人动画全走视频转帧（动作自然度上限高，帧动画级表现力）；失败则回落管线 B（部件动画），本任务书四~六部分照旧执行。实验成本：一条视频几块钱级 + FFmpeg 抠帧，一天内可裁决。

## 五、管线 B 第二部分：动画系统（代码）

- **先通读现役代码再动手**：DoodleMotion、DoodleWeapons、角色渲染/更新管线，输出一段"现状说明"（现役动画怎么驱动、接入点在哪）。
- 升级为**多部件驱动**：每部件独立 position/rotation/scale，动画状态机输出各部件变换。
- **缓动原则（关键，机械感的根源）**：所有运动禁线性插值。约定：ease-out（快出慢收，射击收势/转向）、ease-out-back（过冲回弹，后坐恢复）、sine（呼吸/飘动/转笔）。
- **联动层级**：多部件动作带时间差（如举枪"肩先动→拳 50ms 后跟上"），不做全体同时移动。
- 状态机：`idle / walk / walkShoot(走射) / shoot / hurt / turn`，动作之间平滑过渡（不做瞬切；急停=短缓冲）。
- **所有节奏参数可调**（常量集中一处，标注"待调参"），调参由用户试玩迭代，Codex 只给初值。

## 六、管线 B 第三部分：动作设计清单（姿态剧本，第一优先=走射）

**走射（占游玩时间约 90%，demo 观感大头）**，循环 ~400ms（与射速挂钩）：
```
0ms     鞋块交替前后（相位差 180°）+ 身体起伏 2px（正弦）
0-50ms  躯干微转向目标方向 5-8°（肩先动）
50ms    拳+笔上举到位（比肩晚 50ms = 联动感）
150ms   后坐：全身后移 2px + 头微仰 1px + 笔后撤
200ms   收势缓回（过冲 1px 再回，ease-out-back）
300ms   下一发前摇
```

**待机**：呼吸起伏（正弦，~2s 周期，1-2px）+ 转笔（笔绕拳小转，2s 周期）+ 围巾飘动（正弦摆）。

**走路**：鞋交替 + 身体 2px 起伏 + 落步瞬间下沉 1px（踏地感）。

**转向**：身体先倾再转（ease-out），无瞬切。

**受击**：后仰 2-3px + 闪白（复用现役受击反馈）。

**共 4 套动作**：骨架 A（7 武器，参数分档）+ 变体 B（1）+ 变体 C（1）+ 变体 D（3）。全部可调参。

**骨架 A 参数分档**（每武器独立一套，初值待用户调参）：

| 档 | 武器 | 前摇 | 后坐 | 收势 |
|---|---|---|---|---|
| 标准 | Pistol | 60ms | 1px | 150ms |
| 快节奏 | Chain / Ribbon | 40ms | 1px | 100ms（Ribbon 收势更缓 150ms） |
| 重后坐 | Shotgun | 80ms | 3px | 250ms |
| 瞄准 | Sniper | 200ms | 4px | 300ms |
| 光束 | Ruler | 50ms | 2px | 180ms |
| 最重 | Rocket | 150ms | 5px | 400ms |

**变体 B 近战挥舞（Scraper）**：
```
0ms     拳+刮刀抬起（肩先动 50ms 时差）
100ms   向前挥砍 30° 弧（刀身随转）+ 身体前倾 2px
150ms   命中点：挥砍弧末端 + slash 印章特效（已有）+ 击退强化
250ms   收势回位（ease-out-back 过冲）
```

**变体 C 持续喷射（Airbrush）**：
```
持续中  拳+喷枪平举 + 身体高频微抖（±0.5px）+ 围巾摆幅加大（气流感）
开喷    后坐 1px 后进入持续抖动
停喷    200ms 缓回收势（无三拍，区别于骨架 A）
```

**变体 D 抛掷/放置（Compass / Vortex / Rocket / Mine）**：
```
抛掷    后拉蓄力 150ms（身体后倾 1px）→ 甩出（身体前倾 2px + 手臂甩动弧）
        → 收势 250ms（回旋镖飞回时角色无动作）
放置    身体下沉 3px + 拳下探放置 → 起身（ease-out）
```

**贴图**：12 张武器单帧图衔接 `ArtBatchTask.md` 批 3-4；每武器手持锚点（GRIPS）配置。

**范围纪律**：弹道印章（paintStamp）与弹道行为（速度/散布/伤害）零改动；只加角色动作层差异。

## 九、验收清单（是/否，验收人=用户）

## 十、勿做清单

- 不改风格锁与配色（炭灰/米白/锈红）。
- 不改任何玩法数值、武器数值、掉落、经济。
